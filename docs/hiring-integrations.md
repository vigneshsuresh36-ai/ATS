# Hiring integrations: current state and next steps

See also: [Automations](automations.md) and [Customer installations](customer-installations.md). Interview briefs and the candidate-panel interview preparation are the same AI feature described in the Automations doc.

This inventory is based on code inspection; external service connectivity and production deployment have not been verified.

- Google Calendar: scheduling creates invitations and Meet links when Google Calendar is enabled and configured. Rescheduling preserves the existing event duration and candidate attendee. Test with a controlled Workspace calendar before production use. A configured flag does not prove the connection works.
- Interview reminders: the Automations page can prepare separate emails for candidates and interviewers in a configurable window before an interview. The workflow starts paused, requires review, and uses the existing email provider and scheduler. A cancelled, changed, completed, or past interview invalidates a pending draft. The hourly runner does not guarantee an exact delivery time.
- Careers page: `/careers` lists only explicitly published, open roles for the currently assigned recruiter. From an open requisition, generate a social application link and select List on careers page. A status change to a non-open state or a recruiter reassignment removes the listing; reopening or reassignment requires an explicit new listing. The careers page issues a separate application link so new submissions are recorded as Career Page; existing submissions are not retroactively reclassified. Link the company website to `/careers`; embedding, domain setup and production publishing remain separate work.
- WhatsApp: no provider selected. A real integration needs a business account, approved message templates, consent/opt-out handling, delivery webhooks and credentials. No WhatsApp messages are sent by this project as part of the above changes.
- AI evidence: the candidate panel has an AI evidence summary and interview-preparation function using recorded fields. It does not make hiring decisions; a broader candidate-screening workflow remains to be defined and verified.
- Additional work still to scope: candidate self-service scheduling, consolidated communication history, application acknowledgements, external job-board integrations, expanded offer/onboarding handoff, data retention/consent, and duplicate review. Validate existing functionality before implementing overlapping features.
- Candidate profiles now show the signed-in user's STARSHIP automation email activity, including drafts and provider submission status. This is not a complete cross-channel communication history or confirmed inbox delivery.
- LinkedIn's Job Posting API requires approved partner access and test provisioning; see https://learn.microsoft.com/en-us/linkedin/talent/job-postings/api/overview. Naukri integration capability and access must be confirmed with the account provider. No posting integration has been connected.
